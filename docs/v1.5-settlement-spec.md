# 《Mars Valley》 v1.5 기능 및 내러티브 수정 명세서

작성일: 2026-10-28  
상태: 기획 검토안. 실행 코드와 기존 PPT에는 아직 적용하지 않음.  
기준: 현재 v1.0 MVP, `mvp-spec.md`, `development.md`, `src/`의 실제 구현.

사용자가 제시한 란·루이·선의 과거와 인물 설정을 이번 각색의 전제로 사용한다. 아래 대사는 게임용 창작 대사이며 소설 『일인용 캡슐』의 원문 인용이나 추가 정사 확인을 뜻하지 않는다. 수치·시간·아이템 수량은 구현과 플레이테스트를 위한 초깃값 제안이다.

## 1. 개요 및 변경 요약표

### 1.1 기획 의도

란은 지구 보호소에서 부족한 식량을 선에게 주었고 루이는 살아남지 못했다. 사라진 지구를 목격하고 돌아온 화성에서도 물자는 부족하다. 부상으로 일할 수 없는 선, 설비를 지탱하는 고령의 기술자 홍 선생님, 사람들을 방송으로 잇는 DJ와 함께 첫 겨울을 준비한다.

플레이어의 목표는 **정화·난방 설비를 복구하고, 공동 온실에서 첫 자립 배양토를 완성하며, 최소 한 명의 주민과 생존권을 보장하는 정착을 이루는 것**이다. ‘누가 살아남을 자격이 있는가’는 인물들이 부딪히는 질문이다. 시스템은 사람의 자격이나 생명의 가치를 점수로 판정하지 않는다.

핵심 경험은 다음과 같다.

- 노동을 우선하면 당장의 수리는 빨라지지만, 노동하지 못하는 사람이 버틸 자원이 줄어든다.
- 같은 양을 나누어도 부상자의 호흡과 노동자의 식사 요구는 같지 않다.
- 취약자를 우선하면 치료 여유가 생기는 대신 탐사와 설비 작업에 쓸 몫이 줄어든다.
- 추가 수확, 직접 돌봄, 자신의 몫 양도, 설비 개선으로 선택의 피해를 줄일 수 있다. 누군가의 죽음을 필수 퍼즐 해답으로 만들지 않는다.

기본 경로는 여전히 30분 이내를 목표로 한다. 30분은 강제 게임 오버 시각이 아니며 실제 분량은 검증 대상이다. 란이 사망하면 회차가 종료되는 하드코어 규칙은 유지한다.

### 1.3 불변 조건과 실제 수정 경계

**유지할 것:** HTML/CSS/JS와 Canvas 2D, 현재 파일별 책임, 64×40 타일·32px 월드 타일, 충돌·통로·거점 범위·고정 오브젝트 좌표, 카메라, WASD/방향키, E/Q/Esc, 상하단 HUD 위치·슬롯 수, 기존 정보 모달과 네이티브 dialog, 오른쪽 위 원형 미니맵과 중앙 전체 지도. 새 장면·지도·메뉴·게이지·온도바는 추가하지 않는다.

현재 코드에는 배급 한도, 공동 산소 재고, 주민 사기가 없다. 따라서 **문자열만 교체해서 아래 기능을 구현할 수는 없다.** ‘코드 베이스 유지’는 기존 엔진·모듈·호출 흐름을 유지하고 그 안의 상태·규칙·텍스트를 수정하는 것으로 해석한 검토안이다. 소스의 동작도 전혀 바꿀 수 없다는 뜻이라면 4장의 실제 분배 시스템은 구현할 수 없고 텍스트 연출만 가능하다.

| 기존 책임 위치 | 후속 구현에서 필요한 조정 |
| --- | --- |
| `src/world.js` | 좌표·충돌은 그대로. 오브젝트 이름, 선의 작업 이동 중단, 대피소의 비충돌 상황 상호작용 |
| `src/game.js` | 수색 보상, 배급·소비·돌봄, 타워·흙·정착 판정. 기존 `newGame/tick/act/interact` 흐름 재사용 |
| `src/main.js` | 도입·회의·주민·설비·종료 대사와 버튼 내용, 기존 모달의 재고·배정량 표기 |
| `src/render.js`, `src/map.js` | 같은 설치 면적에서 타워를 표현하고 명칭을 갱신. 카메라·위험 효과·지도 차단 규칙 유지 |
| `src/storage.js` | 신규 상태 검증 및 서로 다른 회차 규칙의 분리. 저장 오류·동시 탭 잠금 유지 |
| `index.html`, `src/style.css` | 슬롯·라벨·설명 문구 교체. 레이아웃과 조작 구조는 유지 |

내부의 `ship`, `pad`, `scrap-*`, `plot-*` 식별자는 좌표와 연결을 보존하기 위해 재사용할 수 있다. 플레이어에게는 ‘탈출선’이나 ‘탑승’으로 노출하지 않는다. ‘중앙 타워’의 중앙은 **공급을 모으는 중앙 설비**라는 뜻이며, 실제 위치는 북동쪽 그대로다.

## 2. 5개 거점 오브젝트 상세 명세

### 2.1 서쪽 공동 온실

범위 `(5,12,12,16)`. 게시판 `(7.5,14.5)`, 급수 장치 `(14.5,14.5)`, 여섯 경작대의 좌표를 모두 유지한다.

| 대상 | E 상호작용과 조건 | 결과 |
| --- | --- | --- |
| 감자 경작대 `plot-0`~`plot-5` | 빈 칸 파종, 급수, 성장 확인, 수확 | 공동 식량에 추가. 미정화 시 성장 360초·수확 1식, 배양토 안착 후 성장 90초·수확 3식 |
| 급수 장치 `pump` | 수리 자재 1개. 이미 복구했으면 재소비하지 않음 | 기존 자동 급수 효과. 배양토 조성에 필요 |
| 게시판 `board` | 다음 주기 배분안, 추가 배급, 의료 키트 사용, 겨울 비축·회수 | 실제 비용과 당사자 의견을 먼저 보여주고 확정 |
| 공동 텃밭 `plot-5` `(12.5,18.5)` | 기존 감자를 수확해 빈 칸으로 만든 뒤 ‘배양토 조성’ 선택 | 정화 필터 1개와 미배정 식량 2식을 사용. 처리 30초 후 E 급수, 90초 관찰 |

미정화 농사의 낮은 생산량은 실제 부족을 만들기 위한 수치 변경이다. 기존 90초·3식 생산을 처음부터 그대로 두면 세 배분안의 비용을 쉽게 초과하여 갈등이 이름뿐일 수 있다. 조작 순서는 유지하고 성장·산출량만 조정한다. 시작 공동 식량은 6식, 기존 두 성숙 작물·두 성장 중 작물 배치는 유지하되 첫 수확부터 미정화 산출량을 적용한다.

배양토 조성의 선행 조건은 **밸브 차단, 급수 복구, 타워 두 모듈 가동**이다. `plot-5`만 조성 중 주민 자동 농사 대상에서 제외하고, 나머지 경작은 계속된다. 처리 30초 도중 이동하면 작업은 취소되지만 이미 투입한 필터·식량과 처리 잔량은 경작대에 남는다. 다시 E를 누르면 이어서 처리하며 재투입하지 않는다. 관찰 중 조성 취소·일반 파종 버튼은 제공하지 않는다.

첫 흙 안착 기준은 다음을 모두 만족하는 것이다.

1. 필터와 유기물 투입 및 처리 완료.
2. E 급수 완료.
3. 정화·난방·급수가 동시에 유지되는 **유효 관찰 시간 90초** 누적. 일시정지나 중단 조건에서는 누적도 정지한다.
4. 새싹이 생존하고 기존 표시부의 독성 반응이 감소했다는 확인 대사 출력.

확인 문구: “싹이 검게 타지 않았어. 이 흙으로 다음 감자를 심을 수 있어.” 이후 `soilSettled=true`. 완료 전 주민이 자동 수확해서 목표를 지우지 않는다. 완료 후 해당 칸도 일반 농사로 돌아간다. 이는 첫 소규모 배양토의 성공이며, 온 행성의 토양이나 다음 겨울 전체를 이미 검증했다는 뜻은 아니다.

### 2.2 북쪽 캡슐 잔해 지대

범위 `(25,4,19,13)`. 북쪽 잔해 세 곳에 필수 모듈과 한정 의료 키트를 확정 배치한다. 나머지 세 잔해의 기존 실외 좌표도 그대로 유지해 보급 경로로 활용한다.

| ID·좌표 | 획득 물자 | 용도·수량 보장 |
| --- | --- | --- |
| `scrap-0` `(26.5,7.5)` | 응급 의료 키트 1개 | 선 치료 / 홍 선생님 증상 완화 / 온실 살균 중 한 번만 사용 |
| `scrap-1` `(35.5,10.5)` | 흙 정화 필터 2개 | 타워 1개, 공동 텃밭 1개. 다른 소모처 없음 |
| `scrap-2` `(41.5,14.5)` | 고효율 난방 코일 1개 | 타워 난방 모듈. 다른 소모처 없음 |
| `scrap-3` `(26.5,31.5)` | 수리 자재 2개 | 급수 1개, 타워 기반 수리 1개. 무작위 손실 없음 |
| `scrap-4` `(54.5,34.5)` | 비상 산소 120 단위 | 공동 산소 재고에 합산. 란에게 자동 독점 지급하지 않음 |
| `scrap-5` `(58.5,24.5)` | 비상 식량 2식 | 공동 창고에 합산 |
| 통신기 `signal` `(43.5,5.5)` | 배급 수요 보고 1회 | DJ 추가 대화와 수요 설명 해제. 보상 자원이나 필수 해독 절차 없음 |

기존 8초 연속 수색, 가까이 접근해야 함, 이동·대화·위험으로 작업 중단, 완료된 잔해 중복 지급 금지를 유지한다. 수색 전 E 안내에 예상 물자를 표시하고 완료 후 실제 지급량을 기록한다. 랜덤 드롭·희귀도·인벤토리 무게는 추가하지 않는다.

핵심 필터·코일이 의료 선택에 소모되거나 부족하게 생성되는 상태를 금지한다. 의료 키트를 어디에 사용해도 타워와 흙 완성 경로는 남아야 한다.

### 2.3 중앙 O₂ 대피소

범위 `(34,20,5,4)`. 진입 시 산소 충전은 기존처럼 자동으로 시작하지만 **란의 산소 배정 잔량과 탱크 여유 중 작은 양까지만** 공급한다. 충전 속도 상한은 기존 초당 8이다. 실내에서는 실외 산소 소모와 추위 피해를 받지 않으나, 대기만으로 배급권이나 의료 효과가 새로 생기지 않는다.

현재 대피소에는 고정 상호작용 오브젝트가 없다. 새 타일·충돌체를 추가하지 않고, 대피소 안에서 다른 가까운 대상이 없을 때 E 안내를 ‘대피소 무전’으로 제공한다. 실행 시에도 대피소 내부 여부를 검사한다. 기존 주민 위치는 이동시키지 않고 무전으로 대화한다.

모달에는 란의 남은 산소 배정량, 공동 미배정 산소, 주민별 호흡 부족 경고를 보여준다. 자신의 몫 양도와 미배정 재고의 추가 배급을 기존 선택 버튼으로 실행한다. 사기·배급 몫이 낮아도 대피소 출입이나 대화를 거부하지 않는다.

첫 대화 예시:

> 홍 선생님: “수리하러 나갈 산소가 있어야 안쪽에도 공기를 보낼 수 있어.”  
> 선: “나는 여기에 누워 있어도 숨을 쉬어. 그걸 낭비라고 부르지 마.”  
> DJ: “누구의 몫을 줄였는지까지 방송할게. 숫자 밖으로 사람을 지우지 말자.”

### 2.4 남동쪽 폐쇄 설비 구역

범위 `(48,28,12,9)`, 누출 범위 `(51,30,5,5)`, 밸브 `(48.5,29.5)` 유지. 누출 안의 기존 초당 체력 2 피해와 진입 전 위험 표시는 유지한다.

- 밸브에 접근해 E를 누르면 기존처럼 즉시 차단된다. 비용은 없고 재차 차단해도 보상이 생기지 않는다.
- 타워 설치 전 차단이 필요하다. 누출 중인 배관으로 중앙 공급을 시작하는 행동은 차단 사유를 표시한다.
- 선이 노동을 하다 이곳에서 사고를 당하는 기존 이벤트는 제거한다. 다리 부상은 시작 전 거주구 붕괴 사고의 결과다.
- 120초 시점의 기존 사건 트리거는 “선의 상처 악화와 의료품 부족” 무전으로 바꾼다. 고정 4분 뒤 사망시키지 않고 실제 건강·산소·돌봄 규칙으로 진행한다.
- 주민을 위험 구역에 보내거나 산소 몫을 대가로 위험 노동을 강요하는 선택은 만들지 않는다. 란이 직접 접근한다.

### 2.5 북동쪽 중앙 흙 정화·난방 타워

범위 `(54,4,8,7)`, 기존 `ship` 위치 `(58.5,7.5)` 유지. 같은 도형 렌더러 안에서 해당 설비의 외형·라벨을 타워로 바꾸되 충돌 면적은 유지한다. 로켓 출발 애니메이션과 탈출 연출은 사용하지 않는다.

타워 작업도 최초 시작에만 자원을 투입하고 진행 상태를 설비에 저장한다. 이동·위험으로 중단해도 진행 잔량을 보존하며 동일 자원을 다시 요구하지 않는다. 완료한 설치는 중복 실행할 수 없다. 홍의 상태에 따라 시작 시 산정한 작업 속도만 고정하고, 작업을 반복 시작해 속도를 중첩하지 않는다.

두 모듈 완성과 흙 안착 후에도 산소 탱크가 무한해지지는 않는다. 생산된 산소를 누구에게 공급할지는 계속 배급 장부를 따른다. 정착은 설비와 분배 원칙을 함께 점검해야 끝난다.

## 4. 온실 게시판: 자원 배분 및 생존 불평등 규칙

### 4.1 시간·재고·배급의 공통 규칙

한 배급 주기는 **진행 중 게임 시간 300초**다. 기존 폭풍 주기와 맞추되 회의는 날씨와 별개로 실내에서 가능하다. 대화·정보·설정·비활성 탭에서는 모든 타이머가 멈춘다.

- 시작 주기 `[0,300)`는 임시 균등안으로 배급한다. 시작 모달에서 비용·권리·첫 회의 시한을 알린다.
- 게시판에서 고른 안은 **다음 주기**부터 적용한다. 같은 주기에 다음 안을 수정해도 현재 배급이나 사기가 재생성되지 않는다.
- 주기 시작 180초 후 기존 무전에 다음 회의를 안내한다. 기한까지 선택하지 않으면 현재 안을 유지하며, 그 결과도 장부에 기록한다. 원정 중 강제 모달을 띄우거나 회의 불참을 즉사로 처리하지 않는다.
- 주기 경계에 남은 배급을 재고로 반환하고, 다음 안의 필요량을 확보한 뒤 사람별로 예약한다. 사망한 사람의 미사용 몫도 한 번만 반환한다.
- 식량은 1식 단위 수확, **0.25식 단위 분배·소비**다. 식량·배급 잔량은 0.25의 배수이며 음수가 될 수 없다. 산소는 게이지와 같은 단위를 사용한다.
- 공동 재고에서 예약한 양을 먼저 빼고, Q·주민 식사·충전 시에는 예약 잔량만 차감한다. 같은 물자를 두 번 빼거나 예약된 물자를 다시 비축하지 않는다.

기존 자원 슬롯 세 개는 ‘공동 식량 / 생존 물자 / 겨울 비축’으로 이름만 바꾼다. 첫 슬롯은 미배정 재고를 표시하고 상세 배급은 게시판·내 정보·게임 정보 모달에 표시한다. Q 버튼의 기존 툴팁·접근성 설명에는 ‘내 배급 잔량’을 표시하고, 버튼 활성 여부도 공동 재고가 아니라 란의 예약 잔량을 따른다. 공동 재고가 0이어도 자신의 몫이 있으면 식사할 수 있다. 가운데 슬롯의 숫자는 미사용 물품 개수 합계이며, 상세에는 키트·필터·코일·수리 자재 수량을 구분한다. 총개수만 보고 서로 대체할 수 있다고 안내하지 않는다. 추가 HUD 패널은 만들지 않는다.

### 4.2 세 배분안의 수치

아래는 **란·홍 선생님·DJ·선 네 명 모두 생존 시 주기당 목표 배정량**이다. 생존하지 않은 사람의 목표량은 제외하지만 사망 기록과 흙의 완성 조건은 줄어들지 않는다.

| 배분안 | 식량: 란 / 홍 / DJ / 선 | 식량 합계 | 산소: 란 / 홍 / DJ / 선 | 산소 합계 | 주민 자동 농사 작업 계수 |
| --- | --- | --- | --- | --- | --- |
| 기여도 중심 `contribution` | 1.25 / 1.25 / 0.25 / 0.25식 | 3식 | 150 / 90 / 45 / 15 | 300 | 1.25 |
| 완전 균등 `equal` | 1 / 1 / 1 / 1식 | 4식 | 100 / 100 / 100 / 100 | 400 | 0.80 |
| 취약자 우선 `care` | 1 / 1 / 1 / 2식 | 5식 | 80 / 80 / 80 / 120 | 360 | 0.80 |

‘기여도’는 객관적인 생명 가치가 아니라 홍이 주장하는 **농사·수리 위주의 제한된 계산 기준**이다. DJ의 방송과 돌봄, 선의 발언은 여기서 낮게 평가되며 대사로 이 편향을 드러낸다.

자동 농사는 기존 24초 작업 주기를 재사용한다. 기본적으로 선을 제외한 건강 30 이상·허기 15 초과인 홍/DJ만 참여한다. 계수는 주민의 유효 작업 시간에 적용하여 같은 자동 작업 1회에 각각 19.2초 또는 30초가 필요하게 한다. 실제 참여 인원과 건강·사기가 낮으면 더 느려진다. **작물 자체의 360초/90초 성장 시간과 란의 수동 E에는 이 계수를 중복 적용하지 않는다.** 란이 직접 일해 저하를 보완할 수 있다.

균등·취약자안의 낮은 계수는 각 안을 선택했다는 도덕적 벌점이 아니라, 고강도 작업자에게 추가 식사가 배정되지 않아 작업·휴식 시간을 늘린다는 단순화다. 같은 식량을 받는 두 안에는 같은 기본 작업 계수를 사용한다. 균등안은 기여도안보다 주기당 1식을 더 소비하며, 취약자안은 2식을 더 소비한다. 취약자안은 의료 키트의 사용처를 자동 확정하지 않는다.

### 4.3 실제 부족분과 추가 배급

재고가 부족하면 해당 자원의 **전체 미배정 재고만**, 선택안의 목표 비율에 맞게 나눈다. 식량은 0.25식 단위 최대 잔여 방식으로 배분하고, 동률은 주기 번호에 따라 돌아가게 하여 배열 첫 주민이 매번 유리해지지 않게 한다. 산소는 1단위까지 같은 원칙으로 나누고 1 미만 잔량은 공동 재고에 둔다.

예: 식량 2식으로 균등안 적용 시 네 명에게 각 0.5식. 창고가 비었으면 모두 0식이다. 부족분은 빚이나 음수 식량으로 생성하지 않는다. 다음 수확이 과거 주기의 결핍을 자동으로 없애지도 않는다.

추가 배급은 게시판 또는 대피소의 기존 모달에서 실행한다.

- 미배정 식량은 0.25식, 산소는 5단위부터 지정할 수 있다. ‘필요 최저선까지’ 버튼도 실제 재고 범위에서만 동작한다.
- 란은 자신의 **미사용** 식량·산소 몫을 양도할 수 있다. 이미 먹은 음식·탱크에 충전한 산소를 환불하거나 타인 탱크에서 강제로 회수할 수 없다.
- 배급 원칙을 바꾸지 않고도 부족한 사람에게 추가 공급할 수 있지만 실제 비용과 공급 대상이 장부에 남는다. 이 경우 엔딩은 안의 이름보다 실제 보장 내역을 따른다.
- 추가 배급·양도로 주기 종료를 미루거나 사기를 반복 획득할 수 없다. 예고된 다음 안은 과거 지급분을 소급 변경하지 않는다.

### 4.5 사기와 업무 지연

사기는 주민별 0~100이며 배급안 선택 버튼을 누를 때가 아니라 **해당 안이 적용된 300초를 완료할 때 한 번** 변경한다.

| 완료한 주기 배분안 | 선 | 홍 선생님 | DJ |
| --- | --- | --- | --- |
| 기여도 중심 | -12 | +6 | -8 |
| 완전 균등 | +2 | -2 | +4 |
| 취약자 우선 | +8 | -8 | +6 |

해당 주기 중 허기 0이 누적 30초 이상이면 추가 -4, 산소 0이 누적 10초 이상이면 추가 -4. 최종 변화는 주민당 주기당 -20~+10으로 제한한다. 사망자는 갱신하지 않는다. 모든 값은 0~100으로 제한한다.

첫 표는 우선 **배분 원칙에 대한 의견 변화**, 추가 값은 **실제로 겪은 결핍**이다. 추가 배급으로 물질적 피해를 막아도 의견 차이는 남을 수 있다. 인물에 대한 호감이나 종교적 선악 수치로 사용하지 않는다.

- 자동 농사에 참여하는 홍·DJ의 사기 30 미만이면 해당 인물의 유효 작업 시간에 0.75, 건강 30~49이면 추가 0.75를 적용한다. 건강 30 미만이면 자동 노동은 쉰다.
- 홍의 타워 수리 지원은 2.5장의 30/45/60초 기준을 사용한다. 건강이 우선이고, 사기가 낮다고 밸브를 열거나 설비를 파괴하지 않는다.
- 선의 사기는 노동 보너스로 환원하지 않고 대사·자기표현에 반영한다. 침묵한다고 식사나 산소를 덜 소비하게 만들지 않는다.
- 반복 위로, 모달 재진입, 장부 방송으로 수치가 무한 상승하지 않는다. 대사 자체는 자원 비용 없이 들을 수 있다.

### 4.6 응급 의료 키트 1개의 사용처

키트는 한 차례 처치에 쓰는 포장 세트다. 한 사람의 만성질환과 외상, 텃밭 독성을 동시에 치료하는 만능 물건으로 표현하지 않는다. 온실 사용은 세트에 포함된 살균·소독 물품을 소모하는 선택이다.

| 선택 | 즉시 효과 | 지속 효과·포기하는 것 |
| --- | --- | --- |
| 선의 동의를 받고 처치 | 키트 -1, 건강 +30, 최대 100 | 상처 악화 중단, 산소 소모 0.30에서 0.20으로 감소. 노동 불능 유지 |
| 홍의 동의를 받고 증상 완화 | 키트 -1, 건강 +25, 최대 100 | 만성질환 악화 중단. 건강 기준을 충족하면 기존 수리 지원 회복 |
| 온실 살균 | 키트 -1 | 600초 안의 다음 미정화 감자 수확 4회까지 회당 식량 +1식, 총 추가 산출 최대 4식. 살균된 수확물의 가식 부분이 늘어난다는 표현. 정화 필터·타워의 대체품이 아니며 병·부상을 치료하지 않음 |
| 보관 | 소모 없음 | 나중에 같은 세 선택 가능. 보관 중이라는 이유만으로 건강·생산 이득 없음 |

사용 전 ‘이번 선택으로 키트가 사라진다 / 다른 두 용도에는 쓸 수 없다 / 약품 없이 할 수 있는 대응’을 함께 표시하고 최종 확인한다. 취소·대상 사망·이미 치료됨·키트 없음이면 아무것도 소비하지 않는다. 사망자를 되살리지 않는다.

선은 30초 직접 돌봄과 충분한 배급으로 키트 없이도 버틸 수 있다. 홍은 적정 배급·난방·휴식으로 건강 저하를 늦추고, 지원할 수 없을 때 란이 직접 수리한다. 온실 살균은 부상 치료의 대가로 주는 추상적 생산 점수가 아니라, 공동으로 나눌 수 있는 최대 4식의 추가 식량이다. 살균 횟수는 실제 감자 수확 완료 때만 줄며 흙 안착 후 수확·배양토 확인에는 적용하지 않는다. 600초가 지나면 남은 횟수는 소멸한다. 이 대안들이 실제 30분 경로에서 가능한지는 수치 검증 대상으로 남긴다. 키트 사용처만으로 선·홍의 사망이나 엔딩을 고정하지 않는다.

### 4.7 회의 모달 표시 순서와 장부

같은 dialog 본문 안에 다음 순서로 표시한다. 표·문단·버튼 내용만 바꾸고 바깥 HUD나 모달 위치는 바꾸지 않는다.

1. 이번 주기와 다음 적용 시각, 공동 미배정 재고, 겨울 비축량.
2. 주민별 건강·허기·산소·사기, 필요한 양, 이미 받은 양, 남은 예약분.
3. 세 안의 식량·산소 총비용, 재고 부족 시 실제 배정 미리보기.
4. 선·홍·DJ의 해당 안에 대한 의견과 작업 시간 변화.
5. 다음 안 확정 / 추가 배급 / 의료품 사용 / 비축·회수 / 돌아가기.

버튼 예시: “다음 5분: 기여도 중심 / 식량 3식, 산소 300 필요”. “공정하다”, “약자를 희생한다” 같은 도덕 판정을 버튼 라벨로 붙이지 않는다. 비용이 부족해도 선택안 자체는 볼 수 있고 실제 지급량을 확인한 후 결정한다.

겨울 비축은 미배정 공동 식량 1식과 비축 1식을 1:1 전환한다. 비축할 때 다음 주기 생존 인원당 최소 1식의 미배정 식량을 남긴다. 회수는 비축 잔량 안에서만 가능하다. 배양토 조성·추가 배급도 실제 미배정 재고를 사용하므로 이미 예약된 식량을 빼앗지 못한다.

장부에는 주기별 선택안·실제 배정·추가 공급·결핍 시간·사망을 저장한다. 짧은 화면 사건 로그 12개와 별도로 필요한 주기 요약을 보관하여 오래 플레이했다고 엔딩 근거가 사라지지 않게 한다. 정책 성향은 **실제로 적용된 시간 비율**로 보여주고, 마지막 버튼 하나나 클릭 횟수로 덮어쓰지 않는다.

## 5. 멀티 엔딩 조건

### 5.1 물리적 정착과 생존권 점검

**물리적 정착 준비 P**는 밸브 차단, 급수 복구, 타워 정화·난방 가동, 첫 흙 안착, 겨울 비축 **8식**을 모두 만족한 상태다. 비축 8식은 시작 공동체 네 명의 첫 겨울 준비 기준으로 고정하며 사망자를 만들면 목표가 낮아지는 방식은 쓰지 않는다. 완료 후에도 플레이를 이어갈 수 있고 최종 종료는 게시판 E의 ‘첫 겨울 점검을 마친다’에서만 확정한다.

**생존권 최저선 R**은 흙 안착 이후의 **종료 직전 가장 최근 두 완료 배급 주기**와 **현재 진행 주기의 보장 상태**를 함께 검사한다. 과거에 한 번 통과하면 영구 유지되는 업적이 아니다. 흙이 주기 도중 안착했다면 다음 경계부터 완전한 주기를 센다. 최소 검증 구간은 600초, 경계 대기까지 최대 900초다.

- 인당 식량 1식 이상. 실제로 먹은 양과 자유롭게 먹을 수 있었던 미사용 예약량을 합산한다. 일방적으로 철회한 몫은 제외한다.
- 인당 기본 산소 60 이상. 선은 해당 주기 중 미치료 시간 ×0.30 + 치료 후 시간 ×0.20으로 산정한다. 전부 미치료면 90, 전부 치료 후면 60, 150초에 치료했다면 75다. 치료 시각을 저장해 과거 필요량을 소급 낮추지 않는다. 란의 실외 탐사에 필요한 추가 산소는 별도 계획 대상이다.
- 직접 돌봄·의료품 접근을 ‘일하지 못한다’거나 ‘회의에 반대한다’는 이유로 금지하지 않는다. 선의 상처가 남아 있으면 그 주기에 키트 치료 또는 직접 돌봄 1회가 제공되어야 한다.
- 허기 0이 누적 30초 이상 또는 산소 0이 누적 10초 이상인 사람이 있으면 그 주기는 불충족이다. 마지막 순간의 추가 배급이 앞선 결핍 시간을 지우지 않는다.
- 한 주기라도 당시 살아 있던 사람이 위 기준을 못 받거나 사망하면 그 주기는 불충족이다. **주기 도중 사망했다고 배급 대상에서 소급 삭제해 통과시킬 수 없다.** 다음 정상 주기 두 번을 새로 점검할 수 있으나 사망 기록은 남는다.

현재 진행 주기는 전원에게 ‘이미 사용한 양 + 아직 접근 가능한 예약 잔량’이 위의 **주기 전체** 식량·산소 기준을 충족해야 한다. 선의 산소 기준은 이미 지난 시간의 치료 전후 필요량에 남은 시간 ×현재 소모율을 더한다. 미치료 선의 돌봄 완화가 현재 유효하거나 키트 치료가 완료되어야 하고, 현재 주기에도 위 결핍 한계 초과·주민 사망이 없어야 한다. 새 주기 경계 직후 종료를 눌러도 새 배급을 검사하므로, 두 주기를 통과한 뒤 현재 몫을 끊고 성공하는 우회는 불가능하다.

R은 숨은 인간성 점수가 아니라 게시판에 그대로 보이는 점검표다. 어떤 배분안이든 추가 배급·실제 돌봄을 포함해 R을 충족할 수 있다. 주민 전원 동의, 사기 만점, 특정 키트 사용처를 정답 조건으로 요구하지 않는다.

### 5.2 네 결말과 판정 우선순위

| 우선순위·결말 | 필요 조건 | 분류·마지막 장면 |
| --- | --- | --- |
| 1. **꺼진 개인등** | 란 건강 0. 어느 단계에서든 즉시 | 생존 실패. 마지막 행동과 실제 사인을 기록. 사망 회차를 이어할 수 없음 |
| 2. **같은 겨울의 네 사람** | 란 생존, P와 R 충족, 선·홍·DJ 모두 생존 | 정착 성공. 선은 앉아서 새싹을 보고, 홍은 다음 점검을 적고, DJ는 네 사람의 이름을 방송. “모두가 같은 일을 하지는 않았지만, 모두의 몫을 남겼다.” |
| 3. **빈자리와 첫 흙** | 란 생존, P와 R 충족, 주민 1~2명 생존 | 상실을 안고 정착 성공. 생존자의 이름과 잃은 사람의 이름·사인을 함께 기록. 설비 성공이 죽음을 지우지는 않음 |
| 4. **켜진 타워, 닫힌 몫** | 란 생존, P 충족 후 종료 확정. R 미충족 **또는** 주민 0명 | 기술적 정착에 그친 실패. 누구에게 무엇이 부족했는지 실제 장부를 보여줌. 혼자 남은 경우에도 성공으로 처리하지 않음 |

P 미충족이면 ‘점검을 마친다’는 종료 확인으로 진입하지 않고 남은 조건을 표시한다. P는 충족했지만 R이나 생존 주민 수가 부족하면 결말 4의 이유와 ‘더 진행해 보장 조건을 맞춘다 / 이 상태로 회차를 마친다’를 명확히 제시한다. 란 사망 판정은 다른 모든 엔딩보다 우선한다. 종료된 상태에서는 소비·성장·수확·대화 보상·부활이 발생하지 않는다.

성향에 따른 결말 부연은 새 엔딩을 추가하지 않고 실제 적용 시간으로 정한다. 한 안이 전체 적용 시간의 50%를 **초과**하면 해당 성향, 아니면 혼합으로 표시한다.

| 성향 | 성공 결말의 부연 | 실패 결말의 부연 |
| --- | --- | --- |
| 기여도 중심 | “추가로 남긴 몫이 선별의 규칙을 바꿨다.” 실제 추가 공급이 있었을 때만 사용 | “수리한 양과 살아 있는 사람의 몫은 같은 장부가 아니었다.” |
| 완전 균등 | “같은 양을 나눈 뒤에도 다른 필요를 다시 살폈다.” | “같은 숫자를 나눴지만, 부족한 몸의 요구는 같지 않았다.” |
| 취약자 우선 | “약한 사람의 몫을 지키며, 지탱하는 사람의 소진도 돌봤다.” | “돌봄을 맡은 사람까지 버틸 조건을 마련하지 못했다.” |
| 혼합 | 바꾼 안과 추가 공급의 실제 순서를 요약 | 선언과 실제 지급이 어긋난 주기를 표시 |

### 5.3 구현 연결·저장 안전성

기존 상태에 필요한 최소 추가 정보는 물품별 수량, 공동 산소 재고, 사람별 배급 잔량·주민 산소·사기, 현재/다음 정책과 주기 번호, 돌봄·치료·살균 상태, 타워 작업 진행, 배양토 진행, 겨울 비축, 주기 요약과 정착 종료 기록이다. 기여 점수·도덕 점수·새 관계 시스템·랜덤 사건 관리자는 만들지 않는다.

현재 `parts`는 수리 자재로 의미를 좁히고, `provisions`는 겨울 비축으로 재사용할 수 있다. 필터·코일·키트는 별도 수량으로 구분하며 합계 부품으로 대체 결제하지 않는다. `engine/lifeSupport`의 저장 필드를 그대로 정화·난방으로 읽는 자동 변환은 금지한다. `escaped` 종료를 정착 성공으로 읽지도 않는다.

정착 규칙의 저장 스키마는 버전 3으로 올린다. 상태는 `active` / `dead` / `settled` / `failed`로 구분한다. 결말 1은 `dead`, 결말 2·3은 `settled`, 결말 4는 `failed`이며 종료 이유와 장부를 함께 저장한다.

v1.0 저장은 **읽기 전용 보관 후 사용자의 명시적 새 v1.5 회차 선택**으로 시작하는 안을 채택한다. 기존 `mars-valley.run.v1`·`mars-valley.terminal.v1`은 그대로 두고, 새 규칙에는 `mars-valley.run.v3`·`mars-valley.terminal.v3`을 사용한다. 기존 사망 표식과 탈출 기록을 삭제하거나 주민 상태·의료품 선택을 임의로 만들어 이행하지 않는다. 확장 지도 v1→v2의 좌표 이행과는 별개의 규칙 변경이다. 새 버전에서도 사망은 이어할 수 없고 새 회차만 시작할 수 있다. v1.5 저장은 현재 정책, 예약분, 자원을 투입한 진행 중 작업·주기 기록을 포함해야 하며 새로고침으로 배급·키트·초기 의료 지원을 재지급하지 않는다. 손상 기록은 자동 덮어쓰지 않고 현행 저장 실패·공통 실행 잠금·중복 탭 방지 처리를 유지한다.

### 5.4 수용 기준과 미검증 항목

후속 구현의 최소 자동 검증 항목:

1. 모든 고정 좌표·충돌·통로·거점·카메라 계산이 v1.0과 같고, 여섯 잔해와 텃밭에 접근 가능하다.
2. 수색은 8초 완료 시 한 번만 지급한다. 필터 총 2개·코일 1개·수리 자재 2개로 필수 시설을 모두 복구할 수 있다.
3. 세 정책의 식량·산소 합계가 표와 일치한다. 부족·사망·동률 배분에서도 재고+예약+소비의 보존식이 성립한다.
4. Q와 주민 자동 식사는 자기 몫만 소비한다. 안전 구역 장기 대기·모달 재진입·정책 변경·새로고침으로 산소와 식량이 복제되지 않는다.
5. 키트 한 개를 세 용도에 동시에 쓰거나 죽은 인물에게 소비할 수 없다. 선 치료 후에도 자동 농사 인원은 늘지 않는다.
6. 직접 돌봄의 주기당 회복, 살균 600초·추가 수확 4회, 다음 정책 적용, 사기 갱신이 중복 실행되지 않는다. 자원 투입형 타워·배양토 작업의 비용과 진행은 보존되며, 미완료 돌봄은 효과가 없다.
7. 배양토 조성 중 자동 파종·수확이 개입하지 않는다. 유효 관찰 90초, 흙 안착 후 최근 두 완전 주기와 현재 주기, 선의 치료 전후 산소 필요량을 정확히 계산한다.
8. 홍의 사망/저사기에서도 수동 복구 경로가 남고, 어떤 키트 사용처도 필수 퀘스트 물자를 소모하지 않는다.
9. 네 결말이 겹치지 않고, 주민 0명은 정착 성공이 아니다. 죽은 주민을 점검 대상에서 소급 제외할 수 없다. 종료 후 상태는 불변이다.
10. v1.0 기록을 정착 성공으로 오인하지 않고, 기존 기록·영구 사망·저장 오류·동시 탭 잠금을 보존한다.

기존 검증 명령은 `npm run check`를 유지한다. 브라우저에서는 E/Q와 지도·모달·경고·작업 중단을 직접 확인해야 한다. **이번 문서는 기획이며 v1.5 구현 테스트를 통과했다는 뜻이 아니다.**

수치 검증이 특히 필요한 항목은 초기 6식과 미정화 360초·1식의 부족 강도, 산소 생성·예약량에 따른 원정 가능 시간, 키트 세 사용처 각각의 전원 생존 경로, 직접 돌봄의 실제 이동·작업 부담, 흙 안착 후 점검 시간을 포함한 30분 목표다. 기여도안+추가 배급이 항상 더 싼 정답이 되는지, 균등안이 추가 보정 없이 항상 안전한지, 취약자안이 고령자를 기계적으로 탈락시키는지도 비교한다.

최소 플레이테스트에서는 ‘누구의 필요가 부족했는지 이해했는가’, ‘동일 배급과 충분한 배급을 구분했는가’, ‘피해를 줄일 대안을 발견했는가’를 묻는다. 한 정책의 선택률이 낮다는 이유만으로 도덕적 실패로 평가하지 않는다. 완성 목표는 정해진 희생자를 고르는 문제가 아니라 **생산·분배·돌봄을 조정해 더 많은 사람이 버틸 조건을 만드는 문제**다.
